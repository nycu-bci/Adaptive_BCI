Round 8: every:1 / every:2 / every:3 (fixed-interval clock, denser than every:4)
Written 2026-11-25, before the run.

Why
  The user asked for it. Round 2's clock curve stops at every:4 (= always, 68.5 finetunes per session).
  These three points show whether accuracy keeps rising with more finetunes, flattens, or drops
  (overfitting to the last few trials, or the gap effect: a finetune 1-2 trials after the previous one
  was worth +0.07 pp in round 2).

Design
  Conditions: every:1, every:2, every:3. every:k finetunes after trial k, 2k, ... of each run (the count resets
  at each run), so every:3 = 13 per 40-trial run. Seeds 0-4 (same as round 2's every:k). Delay 0, adaptive all,
  same start checkpoints and training settings as round 2. Code: simulate_gates_r6.py (= simulate_gates.py at
  ee53e3c, SHA-256 620d675b...). Session-to-host binding copied from round 2, so every session runs on the
  same GPU as its round 2 baseline.
  Expected finetunes per session: about 274 / 137 / 89. About 120k finetunes in total, about 4-5 h on two GPUs.

Analysis (descriptive, no decision rule: this does not test a gate)
  analyze_gates.py on round 8, then evaluate_gates.py on round 2 + round 8 so that the clock curve includes
  every:1-3. Report per condition: accuracy, finetunes per session, and the paired difference vs every:4 (always)
  and vs block (subject level, n = 24, bootstrap 95% CI, Wilcoxon).
  Note for the report: online, one finetune takes 2.5-14 s and one trial about 7 s, so every:1 and every:2 cannot
  run online with delay 0. These points are an offline upper reference for "more finetunes", not a candidate gate.

Prediction (written before the run)
  every:3 about the same as every:4 (within 0.5 pp); every:1 and every:2 not more than 0.5 pp above every:4.
  The curve has flattened from every:8 on.
